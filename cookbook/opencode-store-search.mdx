This notebook demonstrates how to run the OpenCode coding agent on ZeroGPU and ship a real feature with it. You start with Trail Shop, a small React store that lists eight products with no way to search them, connect your ZeroGPU key in OpenCode, pick DeepSeek V4.1 Flash, and ask for a search box in one sentence. The agent reads the code, writes the feature, checks its own work, and the store updates in your browser, in about 20 seconds and for under a cent. By combining OpenCode and ZeroGPU, this notebook walks you through a practical pattern for handing everyday feature work to a coding agent on a low-cost model provider, with no provider configuration at all because ZeroGPU is listed on models.dev.

For the full reference, see the [OpenCode integration guide](/integrations/opencode). For how ZeroGPU's listing works and which other tools read it, see the [Models.dev integration guide](/integrations/models-dev).

In this notebook, you'll explore:

- **OpenCode**: An open-source AI coding agent for the terminal that reads your code, edits files, and runs commands. Its provider catalog comes from models.dev, so ZeroGPU shows up in `/connect` and `/models` with no extra setup. Here it reads the store's code, writes the search feature, and type-checks its own work.
- **ZeroGPU**: A compute-efficient inference provider for apps and agents. We run purpose-built small and nano language models across an edge network for the high-volume tasks you run constantly - classification, extraction, moderation, routing, summarization - at ~10x lower latency and 50%+ lower cost than frontier-model workflows. Auto-scaling, with zero GPU infrastructure to manage. Plug in and you're live.
- **Models.dev**: An open-source database of AI model specifications, pricing, and capabilities that OpenCode reads its providers from. ZeroGPU's listing supplies the endpoint, the API key variable, and the nine chat models you'll pick from.

This setup not only demonstrates a practical application of agentic feature work on a low-cost model, but also provides a flexible framework that can be adapted to other real-world scenarios requiring fast, inexpensive code changes driven by plain-language requests.

## 📦 Installation

First, install the OpenCode CLI. This cookbook uses OpenCode v2:

```bash
curl -fsSL https://opencode.ai/v2/install | bash
opencode --version
```

```
opencode v2.3.0
```

Prefer a package manager? `brew install anomalyco/tap/opencode-v2` or `npm install -g @opencode/cli` installs the same CLI.

ZeroGPU needs no SDK here. OpenCode already knows ZeroGPU's endpoint and models from models.dev, so all it needs is your key. You'll also need Node.js 20 or newer for the store, plus `jq` for one optional catalog lookup. See the [OpenCode integration guide](/integrations/opencode) for every way to connect.

## 🔑 Setting Up API Keys

You'll need to set up your API key for ZeroGPU. This ensures that OpenCode can reach ZeroGPU's models securely.

You can go to [here](https://platform.zerogpu.ai/dashboard) to get an API key from ZeroGPU. The key starts with `zgpu-api-`.

Copy the key now; you'll paste it into OpenCode's `/connect` in a moment, which stores it for every OpenCode session on your machine. If you'd rather keep it in your environment instead, export it under the name models.dev lists for ZeroGPU:

```bash
# Optional: use an environment variable instead of /connect
export ZEROGPU_API_KEY="zgpu-api-..."
```

OpenCode reads environment variables from its shared background server, so if one is already running, restart it with `opencode service stop` after exporting.

## 🗂️ Finding ZeroGPU on Models.dev

OpenCode doesn't ship a hard-coded ZeroGPU integration. It reads ZeroGPU's entry from the models.dev catalog, which you can browse at [models.dev/providers/zerogpu](https://models.dev/providers/zerogpu/) or query directly:

```bash
curl -s https://models.dev/api.json | jq '.zerogpu | {name, api, env, models: (.models | keys)}'
```

```json

  "api": "https://api.zerogpu.ai/v1",
```

That's the whole integration: the endpoint OpenCode will call, the variable it checks for a key, and the nine models it will offer. You'll use `deepseek-v4.1-flash`, listed at $0.30 per 1M input tokens and $1.20 per 1M output tokens, with a 1,048,576-token context window.

## 🔎 Adding Product Search with OpenCode

_This section asks the agent for a real feature in one sentence. OpenCode does the reading, editing, and checking, and every model call behind it runs on ZeroGPU._

Lay out your screen so you can watch it happen: OpenCode in a terminal, `src/App.tsx` open in your editor above it, and the store in your browser.

### Step 1: Ask for the feature

Type this prompt into the OpenCode session and press **Enter**. Then keep your hands off for about 20 seconds:

```text
Add a search box above the products that filters the cards as you type, with a "No products found" message when nothing matches.
```

### Step 2: Watch the agent work

OpenCode reads `src/App.tsx`, the product data, and the card component, then edits `src/App.tsx` in place, so you'll see the file change in your editor. OpenCode's default agent is allowed to edit files and run commands, so there's nothing to approve. Before it replies, the agent checks its own work with a type check or build. That's expected; let it finish.

When the reply lands, the line under it reads `DeepSeek V4.1 Flash · ZeroGPU`. Here's the change it made, from `git diff`:

```bash
git diff
```

```
diff --git a/src/App.tsx b/src/App.tsx
--- a/src/App.tsx
+++ b/src/App.tsx
@@ -1,8 +1,21 @@
+import { useMemo, useState } from "react";
 import Header from "./components/Header";
 import ProductCard from "./components/ProductCard";
 import { products } from "./data/products";
 
 export default function App() {
+  const [query, setQuery] = useState("");
+
+  const filteredProducts = useMemo(() => {
+    const trimmed = query.trim().toLowerCase();
+    if (!trimmed) return products;
+    return products.filter(
+      (product) =>
+        product.name.toLowerCase().includes(trimmed) ||
+        product.category.toLowerCase().includes(trimmed),
+    );
+  }, [query]);
+
   return (
     <div className="min-h-screen bg-stone-50 text-stone-900">
       <Header />
@@ -12,11 +25,29 @@ export default function App() {
           <p className="mt-2 text-lg text-stone-500">Lightweight, weatherproof, built to last.</p>
         </section>
 
-        <section className="grid gap-6 sm:grid-cols-2 lg:grid-cols-4">
-          {products.map((product) => (
-            <ProductCard key={product.id} product={product} />
-          ))}
+        <section className="mb-8">
+          <label htmlFor="product-search" className="sr-only">
+            Search products
+          </label>
+          <input
+            id="product-search"
+            type="search"
+            value={query}
+            onChange={(e) => setQuery(e.target.value)}
+            placeholder="Search products..."
+            className="w-full rounded-full border border-stone-200 bg-white px-5 py-3 text-stone-900 shadow-sm outline-none placeholder:text-stone-400 focus:border-emerald-700 focus:ring-2 focus:ring-emerald-700/20"
+          />
         </section>
+
+        {filteredProducts.length > 0 ? (
+          <section className="grid gap-6 sm:grid-cols-2 lg:grid-cols-4">
+            {filteredProducts.map((product) => (
+              <ProductCard key={product.id} product={product} />
+            ))}
+          </section>
+        ) : (
+          <p className="py-16 text-center text-lg text-stone-500">No products found</p>
+        )}
       </main>
     </div>
   );
```

The agent added a `query` state, filtered products by name and category with `useMemo`, put an accessible search input above the grid, and swapped in the empty-state message when nothing matches. The exact styling and wording change a little from run to run (full width or half width, a different summary), but the behavior is the same every time.

### Step 3: Check the cost

Look at the sidebar for the session's cost. In our test runs, the whole feature took 17 to 18 seconds and cost **$0.0047** and **$0.0060**. OpenCode rounds the sidebar to the cent, so it may read $0.00 or $0.01; either way, it's under a cent.

That figure comes straight from the catalog prices you looked up earlier. A run that sends roughly 15,000 input tokens and gets about 1,000 back costs `15,000 x $0.30/1M + 1,000 x $1.20/1M = $0.0057`.

### Step 4: Try the search

Switch to the browser. There's no need to refresh: Vite already reloaded the page when the agent saved. Click the search box and type a few queries:
