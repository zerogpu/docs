This notebook demonstrates how to run the Kilo CLI coding agent on ZeroGPU and ship a real multi-file feature with it. You start with Marquee, a dark, poster-driven movie-night app whose heart buttons and Watchlist button don't do anything yet, connect your ZeroGPU key in Kilo, pick DeepSeek V4.1 Flash, and describe the feature in one sentence. The agent reads the app, creates a localStorage hook, wires up three components, checks its own build, and the app updates in your browser, in about 23 seconds and for about half a cent. By combining Kilo CLI and ZeroGPU, this notebook walks you through a practical pattern for handing everyday feature work to a coding agent on a low-cost model provider, with no provider configuration at all because ZeroGPU is listed on models.dev.

For the full reference, see the [Kilo CLI integration guide](/integrations/kilo-cli). For how ZeroGPU's listing works and which other tools read it, see the [Models.dev integration guide](/integrations/models-dev).

In this notebook, you'll explore:

- **Kilo CLI**: The terminal edition of Kilo Code, an open-source coding agent that reads your code, edits files, and runs commands. It's a fork of OpenCode and builds its provider list from models.dev, so ZeroGPU shows up in `/connect` and `/models` with no extra setup. Here it reads the app, writes the watchlist feature across four files, and builds the project to check its work.
- **ZeroGPU**: A compute-efficient inference provider for apps and agents. We run purpose-built small and nano language models across an edge network for the high-volume tasks you run constantly - classification, extraction, moderation, routing, summarization - at ~10x lower latency and 50%+ lower cost than frontier-model workflows. Auto-scaling, with zero GPU infrastructure to manage. Plug in and you're live.
- **Models.dev**: An open-source database of AI model specifications, pricing, and capabilities that Kilo reads its providers from. ZeroGPU's listing supplies the endpoint, the API key variable, and the nine chat models you'll pick from.

This setup not only demonstrates a practical application of agentic feature work on a low-cost model, but also provides a flexible framework that can be adapted to other real-world scenarios requiring fast, inexpensive, multi-file code changes driven by plain-language requests.

## 📦 Installation

First, install the Kilo CLI:

```bash
npm install -g @kilocode/cli
kilo --version
```

```
7.8.32
```

Prefer another installer? `curl -fsSL https://kilo.ai/cli/install | bash` or `brew install Kilo-Org/tap/kilo` installs the same `kilo` command.

ZeroGPU needs no SDK here. Kilo already knows ZeroGPU's endpoint and models from models.dev, so all it needs is your key. You'll also need Node.js 20 or newer for the app, plus `jq` for one optional catalog lookup. See the [Kilo CLI integration guide](/integrations/kilo-cli) for every way to connect.

## 🔑 Setting Up API Keys

You'll need to set up your API key for ZeroGPU. This ensures that Kilo can reach ZeroGPU's models securely.

You can go to [here](https://platform.zerogpu.ai/dashboard) to get an API key from ZeroGPU. The key starts with `zgpu-api-`.

Copy the key now; you'll paste it into Kilo's `/connect` in a moment, which stores it for every Kilo session on your machine. Kilo shows the key in plain text while you paste it there, so if you're recording or sharing your screen, store it from a shell instead, where it's masked:

```bash
# Optional: store the key with masked input instead of /connect
kilo auth login --provider zerogpu
```

If you'd rather keep the key in your environment, export it under the name models.dev lists for ZeroGPU, then start Kilo from the same shell:

```bash
# Optional: use an environment variable instead of storing the key
export ZEROGPU_API_KEY="zgpu-api-..."
```

## 🗂️ Finding ZeroGPU on Models.dev

Kilo doesn't ship a hard-coded ZeroGPU integration. It reads ZeroGPU's entry from the models.dev catalog, which you can browse at [models.dev/providers/zerogpu](https://models.dev/providers/zerogpu/) or query directly:

```bash
curl -s https://models.dev/api.json | jq '.zerogpu | {name, api, env, models: (.models | keys)}'
```

```
+    return [];
+  }
+}
+
+export function useWatchlist() {
+  const [saved, setSaved] = useState<number[]>(readStored);
+
+  useEffect(() => {
+    try {
+      localStorage.setItem(STORAGE_KEY, JSON.stringify(saved));
+    } catch {
+      // ignore write failures (private mode, quota, etc.)
+    }
+  }, [saved]);
+
+  const toggle = useCallback((id: number) => {
+    setSaved((prev) => (prev.includes(id) ? prev.filter((x) => x !== id) : [...prev, id]));
+  }, []);
+
+  const has = useCallback((id: number) => saved.includes(id), [saved]);
+
+  return { saved, toggle, has };
+}
```

The agent pulled the watchlist into a `useWatchlist` hook that loads saved film IDs from localStorage (ignoring anything malformed), writes them back on every change, and exposes `toggle` and `has`. It lifted the state into `App`, filtered the grid when the saved view is on, swapped the heading, and added an empty state. The heart got a filled, rose-colored ♥ with `aria-pressed` and a matching label, and the header button got the live count and a highlighted "Saved" state. The exact structure, styling, and wording change from run to run (sometimes the hook lives inside `App.tsx`, sometimes the button reads "All films"), but the behavior was the same in every test.
