This notebook demonstrates how to build a tool-calling agent with Mastra and run it on ZeroGPU with a single model string. You'll build Trail Guide, the gear assistant for a small outdoor store called Trail Shop: it checks a live weather forecast, searches the shop's catalog, and recommends gear with prices and a total. Then you'll chat with it in Mastra Studio and switch to a different ZeroGPU model in the middle of the conversation. By combining Mastra and ZeroGPU, this notebook walks you through a practical pattern for running real agents with tools and memory on a low-cost model provider, with no provider package at all, because Mastra reads ZeroGPU straight from models.dev.

For the full reference, see the [Mastra integration guide](/integrations/mastra). For how ZeroGPU's listing works and which other tools read it, see the [Models.dev integration guide](/integrations/models-dev).

In this notebook, you'll explore:

- **Mastra**: An open-source TypeScript framework for building AI agents and workflows, with tools, memory, and Mastra Studio for chatting with agents locally. Its model router generates its providers from models.dev, so `zerogpu/<model-id>` works with no extra setup. Here it runs the Trail Guide agent, its two tools, and the chat in Studio.
- **ZeroGPU**: A compute-efficient inference provider for apps and agents. We run purpose-built small and nano language models across an edge network for the high-volume tasks you run constantly - classification, extraction, moderation, routing, summarization - at ~10x lower latency and 50%+ lower cost than frontier-model workflows. Auto-scaling, with zero GPU infrastructure to manage. Plug in and you're live.
- **Models.dev**: An open-source database of AI model specifications, pricing, and capabilities that Mastra builds its model router from. ZeroGPU's listing supplies the endpoint, the API key variable, and the nine chat models you'll pick from in Studio.
- **Open-Meteo**: A free, open weather forecast API that needs no key. The agent's forecast tool calls it for a live 3-day forecast of wherever the customer is hiking.

This setup not only demonstrates a practical application of tool-calling agents on a low-cost model, but also provides a flexible framework that can be adapted to other real-world scenarios requiring agents that combine live data, your own catalog, and conversation memory to give grounded recommendations.

## 📦 Installation

First, create the project and install Mastra with all its dependencies. You'll need Node.js 22.13 or later:

```bash
mkdir trail-guide && cd trail-guide
npm init -y
npm pkg set type=module scripts.dev="mastra dev"
npm install @mastra/core @mastra/memory @mastra/libsql zod
npm install -D mastra typescript @types/node
```

That's every package. `@mastra/core` brings agents, tools, and the model router, `@mastra/memory` and `@mastra/libsql` let the agent remember the conversation, and the `mastra` CLI runs Mastra Studio. This cookbook was built with `@mastra/core` 1.85.0 and `mastra` 1.40.1; you need `@mastra/core` 1.85.0 or later, the first release that includes ZeroGPU.

ZeroGPU needs no SDK here. Mastra already knows ZeroGPU's endpoint and models from models.dev, so all it needs is your key. Add a TypeScript config so imports with `.ts` extensions resolve:

```json tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "strict": true,
    "skipLibCheck": true,
    "types": ["node"],
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "outDir": "dist"
  },
  "include": ["src/**/*"]
}
```

See the [Mastra integration guide](/integrations/mastra) for every way to configure a ZeroGPU model.

## 🔑 Setting Up API Keys

You'll need to set up your API key for ZeroGPU. This ensures that Mastra can reach ZeroGPU's models securely. Open-Meteo is free and needs no key, so ZeroGPU's is the only one.

You can go to [here](https://platform.zerogpu.ai/dashboard) to get an API key from ZeroGPU. The key starts with `zgpu-api-`.

Export it in the terminal you'll run Mastra from, under the name models.dev lists for ZeroGPU. Mastra picks it up automatically for every `zerogpu/*` model:

```bash
# Mastra reads this for every zerogpu/* model
export ZEROGPU_API_KEY="zgpu-api-..."
```

Prefer a file? `mastra dev` also loads a `.env` file from the project root. Keep a placeholder in `.env.example` so teammates know which variable to set, and put your real key only in `.env`:

```bash .env.example
# Mastra picks this up automatically for every zerogpu/* model.
# Get a key at https://platform.zerogpu.ai
ZEROGPU_API_KEY=your-api-key
```

## 🗂️ Finding ZeroGPU on Models.dev and Mastra

Mastra doesn't ship a hand-written ZeroGPU integration. Its model router is generated from the models.dev catalog, so ZeroGPU's listing at [models.dev/providers/zerogpu](https://models.dev/providers/zerogpu/) is what puts ZeroGPU in Mastra. You can query the same entry Mastra reads:

```bash
curl -s https://models.dev/api.json | jq '.zerogpu | {name, api, env, models: (.models | keys)}'
```

```json
{
  "name": "ZeroGPU",
  "api": "https://api.zerogpu.ai/v1",
  "env": [
    "ZEROGPU_API_KEY"
  ],
  "models": [
    "deepseek-v4.1-flash",
    "glm-5.3-flash",
    "gpt-4.1-mini",
    "gpt-5.4-nano",
    "gpt-5.6-luna",

    "llama-3.1-8b-instruct-fast",
    "qwen3-30b-a3b-fp8",
    "qwen3.6-35b-a3b"
  ]

```

Mastra publishes the result as its own [ZeroGPU provider page](https://mastra.ai/models/providers/zerogpu), with the same nine models. That's the whole integration: the endpoint Mastra will call, the variable it reads your key from, and the models you can name as `zerogpu/<model-id>`. You'll start on `deepseek-v4.1-flash`, listed at $0.30 per 1M input tokens and $1.20 per 1M output tokens, and switch to `gpt-5.6-luna` ($0.20 in, $1.20 out) later.

## 🔌 Access Tool-Calling Agents with ZeroGPU

ZeroGPU is a compute-efficient inference provider for apps and agents. We run purpose-built small and nano language models across an edge network for the high-volume tasks you run constantly - classification, extraction, moderation, routing, summarization - at ~10x lower latency and 50%+ lower cost than frontier-model workflows. Auto-scaling, with zero GPU infrastructure to manage. Plug in and you're live. In this section, we will make one call to a Mastra agent on DeepSeek V4.1 Flash as an example.

Create a throwaway `check.ts` in the project root. The only ZeroGPU-specific part is the `model` string:

```typescript check.ts
import { Agent } from '@mastra/core/agent';

const agent = new Agent({
  id: 'check',
  name: 'Check',
  instructions: 'You answer in one short sentence.',
  model: 'zerogpu/deepseek-v4.1-flash',
});

const result = await agent.generate('What is one piece of gear every hiker should carry in the rain?');
console.log(result.text);
```


Behind that one line, Mastra found `zerogpu` in its registry, read `ZEROGPU_API_KEY`, and sent the request to `https://api.zerogpu.ai/v1/chat/completions`. You can delete `check.ts` now.

### Step 2: Build the forecast tool

The first tool turns a place name into coordinates with Open-Meteo's geocoding API, then fetches a 3-day forecast in Fahrenheit. It labels the days **Today**, **Tomorrow**, and the next weekday, so the model doesn't have to work out dates:

```typescript src/mastra/tools/get-forecast.ts
import { createTool } from '@mastra/core/tools';
import { z } from 'zod';

// Free Open-Meteo API, no key needed.
export const getForecast = createTool({
  id: 'get-forecast',
  description: 'Get the 3-day weather forecast for a place.',
  inputSchema: z.object({
    location: z.string().describe('City or town name, e.g. "Seattle"'),
  }),
  execute: async ({ location }) => {
    const geo = await fetch(
      `https://geocoding-api.open-meteo.com/v1/search?name=${encodeURIComponent(location)}&count=1`,
    ).then((r) => r.json());
    const place = geo.results?.[0];
    if (!place) return { error: `No place called "${location}"` };

    const { daily } = await fetch(
      `https://api.open-meteo.com/v1/forecast?latitude=${place.latitude}&longitude=${place.longitude}` +
        '&daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max' +
        '&temperature_unit=fahrenheit&timezone=auto&forecast_days=3',
    ).then((r) => r.json());

    return {
      location: `${place.name}, ${place.admin1 ?? place.country}`,
      days: daily.time.map((date: string, i: number) => ({
        day: i === 0 ? 'Today' : i === 1 ? 'Tomorrow' : weekday(date),
        conditions: describe(daily.weather_code[i]),
        highF: Math.round(daily.temperature_2m_max[i]),
        lowF: Math.round(daily.temperature_2m_min[i]),
        chanceOfRain: `${daily.precipitation_probability_max[i]}%`,
      })),
    };
  },
});

function weekday(date: string) {
  return new Date(`${date}T12:00:00Z`).toLocaleDateString('en-US', { weekday: 'long', timeZone: 'UTC' });
}

function describe(code: number) {
  if (code === 0) return 'Clear';
  if (code <= 3) return 'Partly cloudy';
  if (code <= 48) return 'Fog';
  if (code <= 57) return 'Drizzle';
  if (code <= 67) return 'Rain';
  if (code <= 77) return 'Snow';
  if (code <= 82) return 'Rain showers';
  if (code <= 86) return 'Snow showers';
  return 'Thunderstorms';
}
```

### Step 3: Build the catalog search tool

The second tool filters the catalog by category and maximum price. Both filters are optional, so the model can also ask for everything and choose for itself:

```typescript src/mastra/tools/search-products.ts
import { createTool } from '@mastra/core/tools';
import { z } from 'zod';
import { products } from '../data/products.ts';

export const searchProducts = createTool({
  id: 'search-products',
  description: 'Search the Trail Shop catalog. Both filters are optional; call with no input to get everything.',
  inputSchema: z.object({
    category: z.enum(['Footwear', 'Camping', 'Packs', 'Clothing', 'Accessories']).optional(),
    maxPrice: z.number().optional().describe('Highest price in USD'),
  }),
  execute: async ({ category, maxPrice }) => ({
    products: products.filter(
      (p) => (!category || p.category === category) && (maxPrice === undefined || p.price <= maxPrice),
    ),
  }),
});
```

### Step 4: Create the agent

Now the agent itself. The instructions tell it to check the forecast first, then search the catalog, and to answer in a fixed shape: one sentence about the weather, 3 to 4 products, and a total. The `model` line is the whole ZeroGPU integration:

```typescript src/mastra/agents/trail-guide.ts
import { Agent } from '@mastra/core/agent';
import { Memory } from '@mastra/memory';
import { getForecast } from '../tools/get-forecast.ts';
import { searchProducts } from '../tools/search-products.ts';

export const trailGuide = new Agent({
  id: 'trail-guide',
  name: 'Trail Guide',
  instructions: `
    You are the gear assistant for Trail Shop, an outdoor store.
    When a customer describes a trip, check the forecast with get-forecast,
    then look up what the shop sells with search-products.
    Reply with one sentence about the weather, then 3-4 products from the
    catalog as a bulleted list (name, price, and a short reason tied to the
    forecast), then the total. Only recommend products the tool returned.
    For follow-up requests, just update the list and the total.
  `,
  model: 'zerogpu/deepseek-v4.1-flash',
  tools: { getForecast, searchProducts },
  memory: new Memory(),
});
```

DeepSeek V4.1 Flash is the model in Mastra's own ZeroGPU example, and it called both tools in every test run. `new Memory()` is what lets the agent handle a follow-up like "Keep it under $250" later on.

### Step 5: Register the agent with Mastra

The Mastra instance is what Studio loads. It registers the agent and gives memory somewhere to store the conversation. `:memory:` keeps it in memory, so every restart starts with a clean chat:

```typescript src/mastra/index.ts
import { Mastra } from '@mastra/core';
import { LibSQLStore } from '@mastra/libsql';
import { trailGuide } from './agents/trail-guide.ts';

export const mastra = new Mastra({
  agents: { trailGuide },
  storage: new LibSQLStore({ id: 'mastra-storage', url: ':memory:' }),
});
```

### Step 11: Check the cost

Both answers together cost well under a cent. Each one is a few model steps, mostly input tokens: the instructions, the tool schemas, and the tool results. You can price any run from the catalog numbers you looked up earlier. A turn that sends about 6,000 input tokens and gets 200 back on DeepSeek V4.1 Flash costs about `6,000 x $0.30/1M + 200 x $1.20/1M = $0.0020`.
