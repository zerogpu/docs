OpenClaw is an agent runtime that executes work through a plugin system of named skills, each of which the agent can auto-invoke when a user request matches its description. Skills run locally: they shell out to a command-line tool through the agent's Bash tools rather than calling a hosted service. The plugin registry lets teams install and share these skill bundles across projects. Because everything runs on the machine the agent already has, there is nothing to host, register, or expose to the network.

ZeroGPU is an ultra-fast, compute-efficient inference provider for apps and agents. We run purpose-built small and nano language models across an edge-powered network for the high-volume, purpose-specific tasks your app or agent runs constantly. Plug in our OpenAI-compatible API and you're live - zero GPU infrastructure, serverless, auto-scaling by default.

## Overview

This guide walks through installing `zerogpu-openclaw-plugin`, which exposes every ZeroGPU CLI command as an OpenClaw skill. You'll install the `zerogpu` CLI, authenticate once, install the plugin, and see how the agent auto-invokes a skill from plain language and runs the CLI locally. By the end you'll be able to offload cheap, well-defined NLP tasks (summarization, classification, entity and PII extraction, short chat) from your frontier model to ZeroGPU's edge-optimized models, and read a real dollar figure for what each offload saved. Every call happens through the local `zerogpu` CLI: no MCP server, no HTTP client in your code, no infrastructure to run.

## Quickstart

### Prerequisites

- Node.js 20 or newer.
- OpenClaw installed, with plugin support enabled.
- A ZeroGPU [API key](https://platform.zerogpu.ai/dashboard) and Project ID.
- A model ID from the [model catalog](/docs/model-catalog) if you plan to call models by name.

### Get your ZeroGPU API key

1. Sign in to the [ZeroGPU dashboard](https://platform.zerogpu.ai/dashboard).
2. Open **API Keys** and click **Create key**.
3. Copy the key (starts with `zgpu-api-`) and grab your Project ID (UUID) from the project settings page.

### Install the plugin

First install the `zerogpu` CLI that every skill shells out to, then install the plugin into OpenClaw:

```bash
# 1. Install the ZeroGPU CLI (skills shell out to it)
npm install -g zerogpu-cli
zerogpu --version

# 2. Sign in once so every skill call works without re-prompting
zerogpu login

# 3. Install the plugin
openclaw plugins install zerogpu-openclaw-plugin
```

`zerogpu login` prompts for your API key and Project ID and writes them to your config file. For CI or non-interactive setups, pass them as flags:

```bash
zerogpu login \
  --api-key zgpu-api-XXXXXXXXXXXXXXXXXX \
  --project-id 4ed3e5bb-c2ed-4d4a-8a66-2b161a27fd1a
```

To pin a release, install a specific version:

```bash
openclaw plugins install zerogpu-openclaw-plugin@1.4.0
```

### Your first request

Ask your OpenClaw agent in plain language. It picks the matching skill, runs the `zerogpu` CLI locally instead of the host model, and replies with the result plus a savings line:

```text
Redact the PII in this note: "Email John Smith at john@acme.com about invoice 12345."
```

The agent routes to the `redact-pii` skill, which runs `zerogpu redact_pii` on your machine and returns:

```text
Email [PERSON] at [EMAIL] about invoice 12345.

model: gliner-multi-pii-v1 · 2 spans masked
💰 ZeroGPU savings so far: $0.07 (620 host-model tokens offloaded)
```

The raw note never reaches your frontier model. The masked text and a `savings` figure come back instead.

## Usage

You do not call skills by a slash name. You describe the task, and the OpenClaw agent selects the skill whose description matches, then shells out to the corresponding `zerogpu` CLI command through its Bash tools. This section covers every skill in the plugin: what it does, the CLI command it runs, when the agent auto-invokes it, its argument surface, and the shape of the response you'll get back.

Every inference skill returns an object of the form `{ <task fields>, model, usage, savings }`, so alongside the result you always get the model that ran, token usage, and a real `savings_usd` figure for that call.

### How the agent triggers skills

The plugin ships each skill with a description that the OpenClaw agent reads when deciding whether to invoke it for a given user message. You don't have to remember command names: just describe the task. The agent picks based on intent words like "redact", "scrub", "classify by", "summarize", "extract", or "tag this as", and on the structure of the data you supply (a flat label list implies zero-shot; a JSON schema with category axes implies structured classification). Once it picks a skill, it constructs the exact `zerogpu` command, runs it locally, and reports what the CLI returned. It does not fabricate model output.

A short end-to-end run makes the flow concrete. You paste a raw CRM note and ask for several things at once:

```text
Clean up this CRM note for me: redact the PII, pull out the contact and the
next step as JSON, tag the deal stage, and give me a one-line summary.

"Call with Daniel Okafor (daniel.okafor@brightwave.io, +1 206-555-0147) on Tue.
He wants the enterprise quote sent to their AP team by Friday and is comparing us
against two other vendors. Card on file ends 4412. Next step: send quote + book a
technical demo for next week."
```

The agent runs four skills in sequence, each shelling out to the CLI:

```text
1. redact-pii        → zerogpu redact_pii ...
2. extract-json      → zerogpu extract_json ...
3. classify-zero-shot → zerogpu classify_zero_shot ... -l prospecting -l negotiation -l closing
4. summarize         → zerogpu summarize ...
```

And returns a combined result plus the running savings total:

```text
Redacted note:
Call with [PERSON] ([EMAIL], [PHONE_NUMBER]) on Tue. He wants the enterprise quote
sent to their AP team by Friday and is comparing us against two other vendors.
Card on file ends 4412. Next step: send quote + book a technical demo for next week.

Extracted:
{ "contact": { "name": "Daniel Okafor", "email": "daniel.okafor@brightwave.io" },
  "next_step": "Send enterprise quote and book a technical demo" }

Deal stage: negotiation (0.88)

Summary: Daniel Okafor wants the enterprise quote by Friday and is comparing
vendors; next step is to send the quote and schedule a technical demo.

💰 ZeroGPU savings so far: $0.41 (3,910 host-model tokens offloaded)
```

Note the card last-four `4412` is left untouched: the PII model covers standard categories (names, emails, phones, addresses), not project-specific identifiers. Strip those with your own layer or with `extract-entities` and custom labels.

If you ever want to bypass the agent and run a skill's command yourself, every skill maps one-to-one to a `zerogpu` subcommand you can run in any terminal. Each entry below lists the exact command.

### `signin`

Sign in to ZeroGPU and persist your credentials so every subsequent skill call works without re-prompting. Manual only; the agent does not auto-invoke it.

- **Runs:** `zerogpu login`

**Synopsis**

```bash
zerogpu login [--api-key <key>] [--project-id <id>]
```

| Flag | Required | Description |
| --- | --- | --- |
| `--api-key <key>` | optional | API key. Must start with `zgpu-api-`. If omitted, you'll be prompted (masked). |
| `--project-id <id>` | optional | Project ID (UUID v4). If omitted, you'll be prompted. |

On success the API key and Project ID are written to your config file so every other skill can pick them up.

### `status`

Show your current ZeroGPU sign-in status and the masked API key. Manual only.

- **Runs:** `zerogpu status`

Exit code is `0` when signed in, `1` when not. Use it in scripts that need a hard fail before running any inference skill.

### `chat`

Short, single-turn chat reply for things that don't need frontier-level reasoning or prior conversation context. Use it when you'd otherwise burn host-model tokens on a one-liner.

- **Model:** `LFM2.5-1.2B-Instruct`
- **Runs:** `zerogpu chat`
- **Auto-invokes on:** quick factual answers, one-liners, basic rephrasings where you've signalled "use a small model."

**Synopsis**

```bash
zerogpu chat <text> [-i <instructions>]
```

| Name | Required | Description |
| --- | --- | --- |
| `text` | yes | The user message / prompt (quoted). |
| `-i`, `--instructions <instructions>` | optional | System instructions to steer behavior. |

**Example**

```bash
zerogpu chat "Explain WebSockets in two sentences." -i "You are a concise technical writer."
```

Returns raw assistant text (or pretty-printed JSON if the model returned a structured object), alongside `model`, `usage`, and `savings`.

### `chat-thinking`

Same shape as `chat`, but the model returns its reasoning trace alongside the answer.

- **Model:** `LFM2.5-1.2B-Thinking`
- **Runs:** `zerogpu chat_thinking`
- **Auto-invokes on:** short logic / math / word-problem questions where step-by-step reasoning is useful or explicitly requested.

**Example**

```bash
zerogpu chat_thinking "If a train leaves at 3 PM going 60 mph, when does it cover 150 miles?"
```

### `summarize`

Condense a longer passage into a short summary. Use it when you need the gist of a report, ticket thread, transcript, or meeting note without spending host-model tokens on the read.

- **Model:** `llama-3.1-8b-instruct-fast`
- **Runs:** `zerogpu summarize`
- **Auto-invokes on:** "summarize this", "give me the gist", "TL;DR this passage", "condense this into a few sentences."

**Synopsis**

```bash
zerogpu summarize <text>
```

**Example**

```bash
zerogpu summarize "The board met Thursday to review Q3 results. Revenue rose 18% \
year-over-year to $42M, driven mainly by enterprise renewals and a strong launch in the EU \
market. Operating margin slipped to 11% from 14% as headcount grew 30% ahead of the new \
data-center buildout. The CFO flagged rising cloud costs as the top risk for Q4."
```

**Illustrative output**

```text
Q3 revenue grew 18% YoY to $42M on enterprise renewals and EU growth, but operating margin
fell to 11% due to a 30% headcount increase for the data-center buildout, with cloud costs
flagged as the main Q4 risk.
```

### `classify-iab`

Classify text against the **IAB content / audience taxonomy** (standard ad-tech category labels).

- **Model:** `zlm-v1-iab-classify-edge`
- **Runs:** `zerogpu classify_iab`
- **Auto-invokes on:** "what IAB category is this?", "tag this article for ad targeting", "give me the topic taxonomy."

**Example**

```bash
zerogpu classify_iab "The Lakers signed a new point guard ahead of the playoffs."
```

**Illustrative output**

```json
{
  "categories": [
    { "id": "IAB17-44", "name": "Basketball", "confidence": 0.97 }
  ]
}
```

### `classify-iab-enriched`

Enriched IAB classification that returns audience categories **plus** topics, keywords, and inferred user intent.

- **Model:** `zlm-v2-iab-classify-edge-enriched`
- **Runs:** `zerogpu classify_iab_enriched`
- **Auto-invokes on:** "give me topics, keywords, and intent", any request asking for richer ad/audience signals than plain IAB labels.

**Example**

```bash
zerogpu classify_iab_enriched "Compare the Tesla Model Y and the Hyundai Ioniq 5 for a family of four."
```

**Illustrative output**

```json
{
  "categories": [{ "id": "IAB2-1", "name": "Auto Buyers", "confidence": 0.92 }],
  "topics": ["electric vehicles", "family cars"],
  "keywords": ["Tesla Model Y", "Hyundai Ioniq 5"],
  "intent": "comparison-shopping"
}
```

### `classify-zero-shot`

Zero-shot classification against an arbitrary list of candidate labels you supply at call time. The model picks the single best fit and returns scores for all candidates.

- **Model:** `deberta-v3-small`
- **Runs:** `zerogpu classify_zero_shot`
- **Auto-invokes on:** "is this positive, negative, or neutral?", "tag this as bug, feature, or question", "which deal stage is this?"

**Synopsis**

```bash
zerogpu classify_zero_shot <text> (-l <label>...) | (--labels a,b,c)
```

| Name | Required | Description |
| --- | --- | --- |
| `text` | yes | Text to classify (quoted). |
| `-l <label>` | one of `-l` / `--labels` | A single label. Repeatable. |
| `--labels <a,b,c>` | one of `-l` / `--labels` | Comma-separated label list. |

**Example**

```bash
zerogpu classify_zero_shot "I love how fast this laptop boots up." -l positive -l negative -l neutral
```

**Illustrative output**

```json
{ "label": "positive", "scores": { "positive": 0.94, "neutral": 0.04, "negative": 0.02 } }
```

### `classify-structured`

Schema-driven, multi-axis classification. You define each category and its allowed labels, and the model returns one chosen label per category.

- **Model:** `gliner2-base-v1`
- **Runs:** `zerogpu classify_structured`
- **Auto-invokes on:** "classify by sentiment and topic", any request that names multiple classification dimensions with explicit label sets.

**Synopsis**

```bash
zerogpu classify_structured <text> -s '<json schema>'
```

| Name | Required | Description |
| --- | --- | --- |
| `text` | yes | Text to classify. |
| `-s`, `--schema <json>` | yes | JSON object mapping each category to its allowed labels. |

**Example**

```bash
zerogpu classify_structured "Support replied quickly but the fix didn't work." \
  -s '{"sentiment":["positive","negative","neutral"],"topic":["support","billing","product"]}'
```

**Illustrative output**

```json
{ "sentiment": "negative", "topic": "support" }
```

### `extract-entities`

Custom-label named-entity recognition. You define the entity labels; the model finds matching spans with confidence scores.

- **Model:** `gliner2-base-v1`
- **Runs:** `zerogpu extract_entities`
- **Auto-invokes on:** "extract all people, organizations, and locations from this", "find every product mention."

**Synopsis**

```bash
zerogpu extract_entities <text> (-l <label>... | --labels a,b,c) [-t <0..1>]
```

| Name | Required | Default | Description |
| --- | --- | --- | --- |
| `text` | yes | - | Source text. |
| `-l <label>` / `--labels <a,b,c>` | yes (one) | - | Entity labels to extract. |
| `-t`, `--threshold <number>` | optional | `0.3` | Minimum confidence in `[0, 1]`. |

**Example**

```bash
zerogpu extract_entities "Apple CEO Tim Cook met with Sundar Pichai in Cupertino on Monday." \
  --labels person,organization,location -t 0.4
```

**Illustrative output**

```json
[
  { "label": "organization", "text": "Apple",         "score": 0.98 },
  { "label": "person",       "text": "Tim Cook",      "score": 0.97 },
  { "label": "person",       "text": "Sundar Pichai", "score": 0.96 },
  { "label": "location",     "text": "Cupertino",     "score": 0.91 }
]
```

### `extract-pii`

Extract personally identifiable information entities, grouped by category, **without modifying the source text**. Use it when you need structured data about PII (for redaction policies, audits, or downstream tooling) rather than a masked version.

- **Model:** `gliner-multi-pii-v1`
- **Runs:** `zerogpu extract_pii`
- **Auto-invokes on:** "find all PII", "what personal info is in this?", "list emails/phones/names."

**Synopsis**

```bash
zerogpu extract_pii <text> [-t <threshold>] [(-c | --categories) <list>]
```

| Name | Required | Default | Description |
| --- | --- | --- | --- |
| `text` | yes | - | Source text. |
| `-t`, `--threshold <number>` | optional | `0.5` | Minimum confidence. |
| `-c`, `--categories <list>` | optional | `identity,contact` | Comma-separated. Other values: `financial`, `medical`, `credentials`. |

**Example**

```bash
zerogpu extract_pii "Contact Jane Doe at jane@example.com or +1 (415) 555-1212." -t 0.6 -c identity,contact
```

**Illustrative output**

```json
[
  { "category": "identity", "label": "person", "text": "Jane Doe",          "score": 0.96 },
  { "category": "contact",  "label": "email",  "text": "jane@example.com",  "score": 0.99 },
  { "category": "contact",  "label": "phone",  "text": "+1 (415) 555-1212", "score": 0.95 }
]
```

If you want to **mask** PII inline rather than extract it, use `redact-pii`.

### `redact-pii`

Detect PII and replace each span in-line with a `[LABEL]` placeholder. Use it before sharing or logging sensitive text, or before forwarding user input to another model you don't want to expose raw PII to.

- **Model:** `gliner-multi-pii-v1` (with `mask: "label"`)
- **Runs:** `zerogpu redact_pii`
- **Auto-invokes on:** "redact", "scrub", "mask", "anonymize", or "sanitize this for sharing."

**Example**

```bash
zerogpu redact_pii "Email John Smith at john@acme.com about invoice 12345."
```

**Output**

```text
Email [PERSON] at [EMAIL] about invoice 12345.
```

`12345` is not masked: only spans the model recognizes as PII are replaced. Domain-specific identifiers (account numbers, internal ticket IDs) should be handled by your own redaction layer or by `extract-entities` with custom labels.

### `extract-json`

Pull specific named fields out of free text into a structured JSON object, defined by a per-field schema. Each field is declared as `name::type::description`.

- **Model:** `gliner2-base-v1`
- **Runs:** `zerogpu extract_json`
- **Auto-invokes on:** "extract the contact info as JSON", "parse this invoice", "pull these fields out."

**Synopsis**

```bash
zerogpu extract_json <text> -s '<json schema>'
```

**Example**

```bash
zerogpu extract_json "Reach Maria Lopez at maria.lopez@acme.io or 415-555-0188." \
  -s '{"contact":["name::str::Full name","email::str::Email address","phone::str::Phone number"]}'
```

**Illustrative output**

```json
{
  "contact": {
    "name": "Maria Lopez",
    "email": "maria.lopez@acme.io",
    "phone": "415-555-0188"
  }
}
```

### `cost-savings`

Report the cumulative dollars and host-model tokens you've offloaded to ZeroGPU across every skill call. Manual only; the agent surfaces the running figure after inference skills, and you can ask for the total explicitly.

- **Runs:** `zerogpu cost-savings`

**Example**

```bash
zerogpu cost-savings
```

**Illustrative output**

```text
💰 ZeroGPU savings so far: $2.28 (19,650 host-model tokens offloaded)
across 41 calls · top skill: redact-pii ($0.91)
```

### Patterns and recipes

**Sanitize before your frontier model sees raw input.** Route untrusted text through `redact-pii` first when you don't want personal data captured in the agent's transcript or sent to a downstream model. Pair it with `extract-pii` when you also need an audit log of what was masked.

**Cheap router in front of the host model.** Use `classify-zero-shot` or `classify-structured` to triage an incoming message (bug / feature / question, urgent / normal, in-scope / out-of-scope) and only escalate the hard cases to your frontier model. The classifier call costs orders of magnitude less than a host-model turn, and the difference shows up in `cost-savings`.

**Structured extraction over free-form parsing.** For semi-structured text (signatures, invoices, CRM notes, contact blocks), prefer `extract-json` over asking your frontier model to "parse this into JSON." It's deterministic on the schema, faster, and cheaper. Keep field descriptions short and specific; the description is what the model uses to find the span.

**Confidence thresholds.** For NER and PII extraction, the default thresholds (`0.3` and `0.5` respectively) are tuned for recall. Raise `-t` to `0.6` or higher when you need precision (for example compliance-grade redaction lists); lower it when you'd rather over-extract and filter downstream.

## Troubleshooting

**`zerogpu: command not found`** - the CLI isn't installed or isn't on your `PATH`. Run `npm install -g zerogpu-cli` and restart your shell. If you use a Node version manager (nvm, fnm, volta), make sure the shell that launched OpenClaw has the same Node version active, since the plugin shells out to whichever `zerogpu` that shell resolves.

**Skill returns "You're not signed in yet."** - no credentials on disk. Run `zerogpu login` in your terminal (or ask the agent to run the `signin` skill), then confirm with `zerogpu status`.

**Skills don't appear / the agent won't invoke them.** - the plugin isn't installed or enabled. Run `openclaw plugins list` to confirm `zerogpu-openclaw-plugin` is present and enabled; reinstall with `openclaw plugins install zerogpu-openclaw-plugin` if it's missing.

**`Request failed with status 401`** - your API key is missing, revoked, or mistyped. Rotate the key in the [dashboard](https://platform.zerogpu.ai/dashboard) and re-run `zerogpu login`. Keys must start with `zgpu-api-`.

**`Request failed with status 403`** - the key is valid but doesn't have access to the project, or the project doesn't have access to the requested model. Confirm your Project ID matches the project that owns the key.

**`Request failed with status 429`** - you're being rate-limited. Back off and retry with exponential delay, or move bulk jobs to the [Batch API](/docs/batch), which has separate quotas tuned for offline work.

**Wrong skill auto-invoked for a request.** The agent picks based on phrasing. If a skill keeps getting chosen when you don't want it, rephrase to drop the trigger words ("redact", "classify", "extract"), or run the exact `zerogpu` command yourself to bypass the agent's routing.

**Schema parsing errors on `classify-structured` / `extract-json`.** The `-s` flag expects a single-quoted JSON string. On Windows PowerShell, escape inner double quotes or use a here-string. Run the CLI directly to isolate quoting issues from the agent's routing.

**Empty or low-confidence results.** Lower `-t` to surface more candidates, or check that the label set you supplied matches the language of the source text (the underlying models are English-tuned for most label sets). For very short inputs (one or two words), expect lower confidence across the board.

**`cost-savings` shows `$0.00`.** No inference skills have run yet under the current credentials, or you re-authenticated into a different project. The counter is per project; run any inference skill and check again.

## Conclusion

The `zerogpu-openclaw-plugin` turns ZeroGPU's nano language models into first-class OpenClaw skills, so the agent can hand off classification, extraction, and short chat to a cheaper, faster model without leaving the local session or standing up any infrastructure. It's a fast way to keep raw PII out of your frontier model's context, cut token spend on well-defined NLP work, and see exactly what each offload saved.
